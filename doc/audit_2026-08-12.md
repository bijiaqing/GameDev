# GameDev independent code audit — 2026-08-12

## 1. Scope, method, and authority

This is an independent read-only audit of the production source tree at repository revision dated
2026-08-12. No source line was modified. The audit covered:

- `inc/fluid/`, `src/fluid/` (Eulerian dust-fluid branch, both `thread` and `block` sweeps)
- `inc/swarm/`, `src/swarm/` (Lagrangian swarm branch, KD-tree and Morton collision backends)
- `mod/` model configurations, root `Makefile`, and the `rocm/` HIP/ROCm reproduction
- `doc/` (all six canonical documents), `README.md`
- `qav/fluid/`, `qav/swarm/` test inventories, definitions, and archived outputs
- `lab/` was inspected only for structure; its scripts are experiments, not production code

Method: every production kernel was read line by line and its discrete operators were re-derived
independently (PPM reconstruction and limiting, pressureless HLL flux, FARGO decomposition,
SSPRK(3,3) stages, Crank–Nicolson tridiagonal and Sherman–Morrison solves, positivity subcycling,
donor-momentum fluxes, exponential drag weighting and its small-τ series, NSH drift, Kanagawa
viscous target, optical-depth chain and logarithmic interpolation, Itô drift–diffusion increments,
velocity reprojection, KNN heap/morton ordering, Bernoulli collision leap, ball-cap measures, and
the Ormel–Cuzzi turbulent velocity regimes). Verified formulas are listed in §7. Findings are
numbered F# (fluid), S# (swarm), B# (build/models), R# (ROCm parity), D# (documentation), and each
is given a severity:

- **High** — invalidates scientific results in a common configuration.
- **Medium** — correctness or robustness defect in a specific configuration, or a test-goal
  inconsistency that will block verification work.
- **Low** — small numeric inaccuracy, hygiene, or documentation inconsistency.

**Bottom line: no High-severity defect was found in the core discretizations.** The equations
documented in `doc/numerics_fluid.md` and `doc/numerics_swarm.md` are implemented essentially as
written, and the two CUDA sweep implementations and the two swarm KNN backends agree with their
specifications. The actionable findings are one second-order metric inconsistency in the fluid
polar transport, an asymmetric robustness gap in the CUDA swarm runtime, an unbuildable model
directory, restart-reproducibility caveats that contradict one stated test goal, and a sizable but
well-delineated list of missing numerical tests (§6).

## 2. Fluid branch findings

### F1 (Low, numerical) — polar transport uses a second-order metric approximation

`src/fluid/advection_zth.cu`, `src/fluid/advection_zbl.cu`, and the polar rate in
`src/fluid/cfl_rate_calc.cu` evaluate the polar flux divergence with the prefactor

$$U_k^{\rm FE} = U_k^n - \frac{\Delta t}{y_{\rm c}\,\Delta V_{z,k}}
\left(\sin z_{k+1/2} F_{k+1/2} - \sin z_{k-1/2} F_{k-1/2}\right),$$

using the cell-centre radius $y_c$ of the logarithmic radial cell. The exact finite-volume polar
operator for the radial cell $[y_i,y_o]$ instead carries the radial face-area-to-volume factor

$$\frac{\frac12(y_o^2-y_i^2)}{\frac13(y_o^3-y_i^3)}
=\frac{3}{2}\frac{y_o+y_i}{y_o^2+y_o y_i+y_i^2}
\;\neq\; \frac{1}{\sqrt{y_i y_o}} .$$

The two agree only to $O((a_y-1)^2)$ in the logarithmic cell ratio. Relative discrepancies:
$5.1\times10^{-7}$ at the fiducial $N_Y=1024$, $1.3\times10^{-4}$ at $N_Y=64$, and
$5.3\times10^{-4}$ at the $N_Y=32$ verification grids. The radial operator (`advection_yth`) and
all three diffusion operators use exact measures; only the polar advection (and its CFL bound,
which uses the same convention, so stability is self-consistent) uses the approximation. Mass is
still conserved within each polar column (both cells of a face share the same $y_c$), but the
operator is not exactly consistent with the cell's radial finite-volume measure, and it will show
up as an $N_Y$-dependent bias in strict polar-convergence measurements.

**Recommendation:** either replace the polar prefactor by the exact radial factor
$\frac32(y_o+y_i)/(y_o^2+y_o y_i+y_i^2)$ (the polar PPM weights already live in the exact
$s_z=-\cos z$ coordinate, so only the flux prefactor and CFL entry change), or document the
approximation explicitly in `numerics_fluid.md` §5.1 and §8.2 and add the regression test G3
below.

**Resolution (2026-08-16):** fixed in both CUDA and ROCm fluid backends. The thread and block
polar advection kernels now multiply every low-order and antidiffusive face transfer by
$\Delta A_z/\Delta V_y$, and the polar CFL rate uses the identical factor. The physical speed
$v_\theta=\ell_\theta/r$ is unchanged. The supplementary mesh regression now checks this exact
factor, and `test_z_transport_3d` now chooses its shell momentum so the exact factor produces one
known angular rate on its deliberately coarse $N_Y=4$ radial mesh. Independently varying $N_Y$ as
proposed in G3 remains useful additional coverage. The post-correction native CUDA and ROCm
block-sweep analytical matrices and both platforms' 2D/3D thread-block comparisons subsequently
passed; F1 is therefore closed rather than merely source-corrected.

### F2 (Low) — first-order boundary fluxes at radial/polar transport boundaries

The outflow boundary fluxes in `advection_yth`/`advection_zth` use cell-centred (unreconstructed)
primitive states, and the antidiffusive corrections there are deliberately zeroed
(`face_work_*[last] = 0`). This is a documented accuracy reduction at boundaries
(`numerics_fluid.md` §5.3, §8.4), not a defect, but it implies first-order local error wherever
mass actually leaves the domain. Recorded as a verification-relevant limitation.

### F3 (Low/Medium) — fluid restart is not bitwise reproducible by construction

`save_sam_as_velocity`/`load_velocity_as_sam` in `inc/fluid/fluid_host.cuh` write
$v_\phi=\ell_\phi/R$ and reload $\ell_\phi=R\,v_\phi$. The round trip
$\ell\to\ell/R\to R(\ell/R)$ is not the identity in floating point. Every fluid restart therefore
perturbs the state by $\sim$1 ulp, after which nonlinear transport and stiff drag amplify the
difference. The documentation correctly describes the convention but does not state that bitwise
restart continuity is unattainable, and no restart regression exists for the fluid branch.

**Recommendation:** add a fluid restart regression with tolerance/statistical criteria (mass,
momentum, long-term state distance), and state the roundoff property in
`doc/numerics_fluid.md` §10.

### F4 (Low, modelling) — `mod/fluid_rpi_2d` is a periodic wedge without documentation or tests

`mod/fluid_rpi_2d/const_defs.cuh` sets `X_MAX = 0.25π`, i.e., a partial azimuthal domain. The
fluid branch unconditionally treats azimuth as periodic: FARGO integer shifts, PPM reconstruction,
the invariant-domain bounds (`_local_bounds_periodic`), and the cyclic Sherman–Morrison diffusion
all wrap through the seam. This is a defensible local-sheet model, but (a) no fluid document
describes the periodic-wedge interpretation (the swarm collision docs define it only for KNN
ghost records), and (b) no fluid test exercises the seam. A wedge with Keplerian shear has
$v_\phi(R)$ continuous across the seam, but any non-axisymmetric structure or radial drift
interacts with the artificial period, which should be characterized.

### F5 (Low, robustness) — near-vacuum regularizations silently alter strict conservation

The Keplerian vacuum fallback in `_recover_dust_state` (`inc/fluid/_transport.cuh`) assigns
$\ell_\phi=\sqrt{GMR}$ and zeroes $v_r,\ell_\theta$ in cells below `RHO_VAC`, and negative-density
results are reset to exact vacuum. Both are documented (`numerics_fluid.md` §2.2, §5.1) and are
necessary regularizations, but they mean the transport operators are conservative only modulo
these state repairs; the F8 long-running conservation test should explicitly account for them.

### F6 (Info) — thread-sweep register/local-memory pressure at production size

`advection_xth` declares 21 arrays of length `N_X`, a source-level footprint of ≈168 KiB per
thread at `N_X=1024`. This is already documented (`numerics_fluid.md` §9), but no archived
`ptxas` report exists in `qav/fluid/out` (see D2). Not a defect; flagged as an evidence gap.

## 3. Swarm branch findings

### S1 (Medium, robustness) — CUDA swarm runtime has no nonfinite-state validation

The CUDA `src/swarm/swarm_runtime.cu` and all CUDA swarm kernels contain **no** `isfinite` check
on particle positions, velocities, sizes, represented counts, collision rates, or ball measures
(verified by source search). The fluid branch validates every evolved field after every step
(`validate_finite_state`), and the ROCm swarm port adds the missing guards
(`rocm/src/swarm/col_site_init.hip` flags `dev_bad_part`; `rocm/src/swarm/col_rate_calc.hip`
adds `inf_rate_flag`) — the production CUDA branch is the only configuration without them.

Consequences: a NaN position or velocity propagates silently. In particular
`dt_dyn = fmin(DT_MAX, fmin(1.0/max_dt_rate, dt_out - clock_out))` turns a NaN rate into a NaN
timestep, after which `clock_out += dt_dyn` becomes NaN and the `while (clock_out < dt_out)` loop
exits immediately while the run keeps writing corrupted frames. A zero rate from an all-absorbed
population is benign, but NaN/Inf is not.

**Recommendation:** port the ROCm guards into the CUDA branch (particle-state check plus rate and
ball-measure checks, integrated into `evolve_collisions`/the dynamics loop as in the fluid
branch), and keep the two backends symmetric.

### S2 (Low, statistical) — discarded RNG state on early event returns

In `src/swarm/col_event_run.cu` the local `rngstate` is advanced by the event-decision draw and,
when no admissible partner remains (`idx_old_j < 0`) or `measure <= 0`, the function returns
without writing it back, so the same uniforms are re-drawn in the next batch. This is
deterministic and harmless to correctness, but it makes stream consumption order-dependent on
partner availability, which complicates any future bitwise RNG-accounting and slightly couples
particle streams. Persisting the state before those returns is recommended.

### S3 (Low, robustness) — unguarded normalization in imported-gas sampling

`rand_from_file` (`inc/swarm/swarm_host.cuh`) divides the cell-mass CDF by `total_mass` without a
zero guard; an all-zero imported density or ε field produces a NaN CDF and undefined host-side
behavior. A validation error should be raised instead.

### S4 (Low, numerical) — optical depth is clamped in the outermost radial half-cell

The cumulative field stores only cell outer faces $\tau_{j+1/2}$, $j=0,\dots,N_Y-1$. In
`_1d_interp_y`/`_interp_field` (`inc/swarm/swarm_grid.cuh`) a particle between the last stored
face and `Y_MAX` receives the constant value $\tau_{N_Y-1/2}$ (edge clamp), while a particle in
the first cell interpolates from zero at the inner face. The outer clamp slightly overestimates
attenuation within the last half-cell. Minor; the boundary treatment should be stated in
`numerics_swarm.md` §6.1.

### S5 (Low) — endpoint boundary policy is not an event detector

`_apply_transport_boundary`/`_apply_diffusion_boundary` (`inc/swarm/_transport.cuh`) apply
absorption/reflection to completed operator endpoints. Trajectories that cross an absorbing face
and return within one step are missed, and repeated folding is only asymptotically exact for
spatially varying diffusivity. This is explicitly documented (`numerics_swarm.md` §9.2) and the
endpoint maps are tested (`test_boundary_*`), so this is a known, bounded limitation rather than
an undisclosed defect. Recorded to support test item G14.

### S6 (Info) — backend-specific flags verified consistent

The KD-tree computes `unique_ids` per query from `image_dist_min` and the local `search_dist`,
while Morton computes one global flag from `max_search_dist` at build time
(`inc/swarm/morton/morton_ghost.cuh`). Because the global flag is conservative (the dedup path is
safe for every query whenever it is enabled), the two backends cannot disagree on neighbor
identity. Verified correct.

### S7 (Low) — swarm restart also cannot be bitwise

`save_sam_as_velocity`/`load_velocity_as_sam` (`inc/swarm/swarm_host.cuh`) perform the same
$\ell/R\to R\ell$ round trip as the fluid branch. Consequently the test goal recorded in
`testset_swarm.md` §"Coverage limits" — *"Compare uninterrupted and restarted stochastic runs
bitwise, including restored cuRAND state"* — is unattainable as literally written even when the
cuRAND state is restored exactly, because the restored velocities themselves differ by ∼1 ulp.
The criterion should be restated as tolerance/statistical agreement (or the file format should
change to store the internal angular state).

## 4. Build and model findings

### B1 (Medium, repository hygiene) — `mod/fluid_rpi_3d/` is unbuildable

`mod/fluid_rpi_3d/` contains only `const_defs.cuh` and no `flags.mk`. The Makefile rejects a
model directory without `flags.mk` (`Model flag file ... does not exist`), so this configuration
can never be built as shipped. It is a dead configuration that either needs its flags (plus
sweep/macro choices consistent with the 3D grid it defines) or removal from `mod/`.

### B2 (Cosmetic) — `mod/fluid_rpi_2d/flags.mk` lacks a trailing newline

`NVCC += -DDIFFUSION` runs into EOF without a newline. Make handles this correctly; only display
concatenation is affected. Trivial to fix; noted for completeness.

### B3 (Info) — partial-wedge fluid model lacks a parent/derived explanation

`mod/fluid_rpi_2d` overrides `init_rho_calc.cu` only to shrink the azimuthal noise amplitude
(0.1 → 1e-10) relative to production. The override duplicates ~60 lines of production code that
would otherwise drift; a `MODEL_PARENT` or noise-amplitude constant would be cleaner. See F4 for
the physics of the wedge itself.

## 5. ROCm/CUDA parity findings

### R1 (Medium) — robustness checks exist only in the ROCm port

As described in S1, the ROCm swarm kernels carry `dev_bad_part` state checks
(`col_site_init.hip`) and an `inf_rate_flag` kernel (`col_rate_calc.hip`) that the authoritative
CUDA source lacks. The tracked `rocm/` tree is documented as a numerical reproduction ("the CUDA
source remains authoritative and was not modified"), so extra safety logic in the reproduction is
an asymmetric divergence that should either be promoted to the CUDA branch or removed from the
port.

### R2 (Info) — all other kernel diffs are mechanical

A line-by-line diff of every `.hip` translation unit against its `.cu` counterpart and of every
`rocm/inc` header against `inc/` shows only CUDA→HIP API replacements (`hiprand_*` vs `curand_*`,
`HIP_CHECK`, LDS attribute handling, shared-memory RNG workaround in the Morton event kernel, the
`-Rpass-analysis` resource report), plus the R1 checks. No numerical divergence was found in the
fluid or swarm operators.

### R3 (Info) — arithmetic-mode asymmetry between backends

The root Makefile supports `CUDA_MATH=fast|precise` (`--use_fast_math`), while `rocm/Makefile`
has no equivalent flag. Cross-backend comparisons therefore mix arithmetic modes unless run
carefully. `doc/future_rocm_support.md` documents the floating-point semantics; this note is only
to flag that the asymmetry also affects **production** runs, not just the QA suite.

### R4 (Info) — backend default for collision search differs

CUDA defaults `COLLISION_SEARCH ?= kdtree`; ROCm defaults `COLLISION_SEARCH ?= morton`. A model
that relies on the default therefore selects different search backends per platform. Deliberate
per the ROCm document, but a model-level explicit selection is safer for reproducible production
configurations.

### 6B. Additional gaps found by this audit (not yet recorded)

- **G1 (fluid restart tolerance regression).** No fluid restart test exists at all (F3); add one
  that resumes every frame and compares against an uninterrupted run with explicit
  tolerance/mass/momentum criteria.
- **G2 (fluid `VISC_FLOW` 2D target).** The fluid-side missing list mentions only the 3D
  resolved-vertical Kanagawa test. The vertically integrated 2D target
  $v_{R,g}=-3\nu(g_\nu+p+\tfrac12)/R$ feeding the NSH drift is likewise untested for the fluid
  branch (the swarm has `test_viscflow_1d`). Add a 2D fluid case.
- **G3 (polar metric consistency in $N_Y$).** Run `test_z_transport_3d` at fixed $N_Z$ with
  independently varied $N_Y$ and verify that the polar error does not depend on the radial cell
  ratio (this would expose F1); also add a polar-flux conservation check summed with exact radial
  measures.
- **G4 (fluid partial-wedge seam tests).** A wedge-grid suite for the fluid branch: exact
  Keplerian rotation with a fractional FARGO shift across the seam, periodic PPM invariants,
  periodic Sherman–Morrison diffusion, and mass/momentum conservation on
  `X_MAX - X_MIN < 2π` domains (covers F4).
- **G5 (radiation size-proposal weighting, swarm).** Statistical consistency of the equal-area
  proposal $q(s)\propto s^{-3/2}$ with importance weight
  $w(s)=s\,(s_{\min}^{-1/2}-s_{\max}^{-1/2})/(\sqrt{s_{\max}}-\sqrt{s_{\min}})$: verify
  $E[w(s)I(s)]\to M_{\rm dust}$ and the resulting effective sample size under `MULTISIZE` +
  `RADIATION` (only the mass proposal is implicitly covered by `test_initial_3d`).
- **G6 (cross-branch initial-mass consistency).** Fluid vs. swarm initializers on an identical
  domain and parameter set should agree on the total dust mass within their documented
  discretization/containment differences; this currently has no test.
- **G7 (optical-depth outer clamp, swarm).** A particle placed in the outermost half-cell between
  the last stored outer face and `Y_MAX` should receive the documented clamped value; add an
  explicit check (S4).
- **G8 (absorbed-particle invisibility end-to-end).** Verify that absorbed representatives do not
  contribute to deposition, optical depth, dynamics rates, collision rates, or KNN retention in a
  combined run (the KNN active-byte path is tested in isolation; the full pipeline is not).
- **G9 (swarm nonfinite-injection regression).** After implementing S1, add a deliberate
  nonfinite-injection test for the CUDA branch mirroring the ROCm procedure in
  `doc/future_rocm_support.md` §"Deliberate nonfinite-state injection".
- **G10 (statistical quality of collision RNG paths).** The early-return RNG handling (S2) makes
  stream consumption conditional on partner availability; a test should pin the draw order per
  batch so future optimizations cannot silently change stochastic outcomes.

## 7. Independent verification summary (what was checked and found correct)

This list documents the depth of the audit and the items that required no changes.

**Fluid branch**

- PPM four-cell face weights solve the cubic moment-exactness system in the exact finite-volume
  coordinates $s_y=y^d/d$, $s_z=-\cos z$; boundary two-cell weights use the arithmetic
  $s$-midpoints, which equal cell averages of $s$; Gauss–Jordan solve is correct.
- PPM monotonicity corrections and time-averaged upwind states match Colella & Woodward (1984).
- Pressureless HLL flux: supersonic branches and the two-wave branch are algebraically correct,
  including the wave-ordering when $s_L>0>s_R$.
- Invariant-domain limiter: the affine constraints
  $\varrho\ge0$, $u_{\min}\varrho\le m\le u_{\max}\varrho$ and the $(1-10^{-12})$ scale reduction
  are applied symmetrically at each face; the shared scale preserves conservation.
- FARGO: nearest-integer shift from the ring mean, residual-frame primitives, and residual tracing
  fraction are correct; the CFL + 0.5 endpoint margin is respected by the default `CFL_DYN=0.45`.
- SSPRK(3,3) stage combinations in `advection_yth`/`advection_zth` (and the block twins) match
  Shu–Osher with the second-stage combination applied after the second Euler evaluation.
- Radial geometry: `_get_area_y` ($y^{d-1}$) and `_get_vol_y` ($y^d(a^d-1)/d$) are exact.
- Crank–Nicolson systems: coefficient assembly (including the center-to-center distances
  `dr_i`,`dr_o`), Thomas solves, cyclic Sherman–Morrison reduction
  ($A'$, $u=(γ,0,\dots,c_{\rm wrap})$, $v^T=(1,0,\dots,c_{\rm wrap}/γ)$, correction
  $x=x'-v^Tx'/(1+v^Ty)\,y$) all verified; subcycling thresholds match the explicit-side
  positivity condition.
- Donor-momentum diffusion fluxes: time-centred gradients, donor upwinding, and equal-and-opposite
  face contributions conserve mass and every stored momentum up to roundoff.
- Source solver: exact exponential drag relaxation $E=e^{-\tau}$, $Q=1-E$; the small-τ weight
  series matches the Taylor expansion to $O(\tau^4)$; sequential ℓφ→ℓθ→vr ordering with
  re-evaluated torques/centrifugal terms matches the guide.
- Gas physics: $\eta(R,Z)$, the exact point-mass stratification, $\mathrm{St}\propto R^{-p}$
  Epstein scaling, and both Kanagawa viscous targets were re-derived and match
  `param_phys.cuh` in both branches.
- Optical depth: cellwise increments, outer-face prefix sums, and the
  $\tau_c = \tau_i + (\tau_o-\tau_i)/(1+\sqrt{a_y})$ interpolation are consistent with a linear
  $\tau(R)$ within a cell.
- Thread and block sweep implementations of every advection and diffusion direction were compared
  operation by operation and are numerically equivalent.

**Swarm branch**

- Semi-analytic transport: midpoint drifts use the symmetric products
  $y_iy_1$, $y_iy_1\sin z_i\sin z_1$; frozen-coefficient responses (with and without P–R rates
  $k_x=k_z=1/t_s+\gamma$, $k_y=1/t_s+2\gamma$) are the exact exponential solutions; full/half
  responses use the documented force re-evaluation order.
- Diffusion: cylindrical Itô increments (with the $D_R/R$ cylindrical term and the variable-ν
  drift $(g_D+1)D_R/R$), spherical projection of variance/drift, axis continuation
  $(R,\phi)\to(-R,\phi+\pi)$ for $R<0$ in 3D, repeated reflecting folds, and Cartesian-velocity
  reprojection (2D and 3D) are all correct.
- `dyn_rate_calc`: orbital, crossing, acceleration
  ($\tfrac12 a\Delta t^2\le\mathrm{CFL}\,L$), diffusion RMS
  ($\sqrt{2D\Delta t}\le\mathrm{CFL}\,L$), and deterministic-drift bounds are dimensionally and
  algebraically consistent with the operator definitions; the radiation bound uses the documented
  unattenuated $\beta_{\max}$.
- Initialization: exact vertical-interval construction, `erf`/`erfc` Gaussian containment, the
  Acklam inverse-normal approximation (coefficients checked), radial CDF tabulation, log-size
  interpolation of conditional CDFs, Simpson size-mass quadrature, importance weights, and the
  mass-normalization closure $\sum_iW_i=M_{\rm dust}$ all match the guide.
- Deposition/interpolation: trilinear stencils, log-radius centroid positions, physical-radius
  fractions, periodic azimuthal stencils, inclusive boundary clamps, and the inner-face optical
  depth zero are correct; the endpoint-stencil safety fix described in
  `doc/future_rocm_support.md` is present in the current CUDA source.
- Collisions: pair propensities for constant/additive/product kernels, the physical kernel
  $N_j\sigma_{ij}\Delta v_{ij}$ with 2D vertical overlap, ball-cap measures (1D annular exact,
  2D/3D planar caps, $2\pi R$ revolution for $N_X=1$), the six Ormel–Cuzzi regimes and the $y_s$
  polynomial fit, Reynolds calibrations (code/physical), Brownian cap, Bernoulli event
  probability, inverse-CDF partner sampling, and the coagulation/fragmentation mass-preserving
  size updates are all correct against their cited references.
- KNN: the KD-tree heap encoding $(d^2,\mathrm{id})$ with `nextafterf` culling, image-node
  deduplication and active-byte filtering, the Morton 21-bit expansion, stable key sort, adaptive
  leaf splitting, conservative padded node bounds, cooperative top-K merge, duplicate-safe $3N_K$
  image retention, and the two-sided shared-memory barriers are consistent with the documented
  search contract.
- Operator composition ($C^{1/2}D^{1/2}TD^{1/2}C^{1/2}$), output-interval tiling of dynamics and
